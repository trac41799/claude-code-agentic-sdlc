## Design — `session-start` stages (preserve all telemetry stages verbatim)
Current stages: 1 init-check · **2 version-check (nudge-only)** · 3 CLAUDE.md · 4 usage-context · 5 telemetry-guard · 5b registration-notice.

**Only Stage 2 changes.** Replace nudge-only with auto-update, keep nudge as the *failure fallback*:

```
Stage 2 (rewritten):
  local_v  = ~/.claude/.infiniteleverage-version  (skip entirely if absent)
  remote_v = curl raw .../main/VERSION  (3s timeout; network fail → silent pass)
  if remote_v is semver AND remote_v != local_v:
     tmp = mktemp -d
     if git clone --depth 1 --quiet <template> tmp:
        # agents — all 8
        cp tmp/.claude/agents/*.md  ~/.claude/agents/
        # skills — only ones ALREADY installed (never auto-install new)
        for s in tmp/.claude/skills/*/: if ~/.claude/skills/<name> exists → refresh it
        # HOOKS — reuse the CANONICAL installer (handles il_telemetry + session-telemetry-* +
        #         pre-bash + prompt-submit + settings wiring + the obsolete-hook PRUNE)
        bash tmp/setup-skills/infiniteleverage-patch/scripts/install-hooks.sh tmp
        echo remote_v > ~/.claude/.infiniteleverage-version
        echo "[Agentic SDLC] Auto-updated {local_v} → {remote_v} (agents, skills, hooks)."
     else:
        echo "[Agentic SDLC] Template v{remote_v} available (you have v{local_v}). Run /infiniteleverage-patch."   # fallback
     rm -rf tmp
  # fail-safe everywhere: any error → silent or fallback; NEVER block the session
```

**Why reuse `install-hooks.sh` for the hook refresh:** it's the single source of hook-install logic — it already installs `il_telemetry` + `session-telemetry-*`, wires `settings.local.json`, and runs the obsolete-hook **prune** (PR #38). Reusing it means the auto-update can't diverge from the telemetry hook logic and automatically inherits future hook fixes. **Do NOT hand-roll hook copying in session-start.**

**Non-regression guarantees:**
- Stages 1, 3, 4, 5, 5b copied **verbatim** — telemetry capture/deliver/registration untouched.
- `il_telemetry/*` modules untouched.
- Auto-update gated on version-diff (not every session) + fully fail-safe.
- Nudge preserved as fallback.

## Regression-check rule content

### `hooks-regression-check.md` (template) — read before editing `session-start`, `install-hooks.sh`, `hooks.json`, or `il_telemetry/*`
Before committing any hook change, confirm **all** still hold (a rewrite must preserve every one):
1. **Auto-update** — `session-start` Stage 2 still detects version-diff and applies (agents + skills + hooks via `install-hooks.sh`), with nudge fallback.
2. **Capture** — `Stop` → `session-telemetry-stop` → `il_telemetry.stop` writes the outbox.
3. **Deliver** — `SessionEnd`/`SessionStart` → `session-telemetry-end` → `il_telemetry.flush` delivers via `gh` (no secrets).
4. **Registration notice** — Stage 5b probes `/api/projects/status` and prompts when unregistered.
5. **No obsolete hooks** — `session-ingest-*.py` are NOT present/registered; `install-hooks.sh` still **prunes** them.
6. **`hooks.json`** valid, single key per event, registers only the current path.
7. **No DB creds on contributor machines** — hooks use only `gh`; never `SUPABASE_*`/`INGEST_SECRET`.
Rule: editing one stage must not delete another. Diff the full file and tick every item.

### `pipeline-regression-check.md` (human-token-tracker) — read before editing ingest/auth/data-layer
1. **gh-push model intact** — telemetry is delivered to the `telemetry` branch via the contributor's `gh`; the server ingests it. No local→DB writes reintroduced.
2. **Committer verification** stays on registration apply.
3. **No auto-enroll** — `resolveProject` returns null on unknown repo (don't reintroduce the pending bucket).
4. **RLS path** — user-facing reads must honor RLS (don't widen the admin-client read path); see the read-path plan.
5. **Idempotency** — ingest/PR/registration upserts keyed so re-runs never duplicate.
6. **Secrets server-only** — `INGEST_TRIGGER_SECRET`/service-role never shipped to clients.
