The Concept

Humans orchestrate.
Agents act.

Most "AI tools" wait for prompts. This template installs a standing team of role-based agents that each own a job, follow hard rules, and hand work to one another — like a real company, running on your machine.

Not a chatbot

A team of roles

Four fixed agents — PM, Developer, QA, DevOps — each with its own remit.

Not magic

Agents are folders

Every agent is a plain Markdown file plus skills. Transparent, versioned, editable in git.

Not throwaway

Work outlives you

Context lives in the repo, not the chat. Any machine or session picks up exactly where the last left off.

The Purpose

Why this exists

  • Solo operators can't staff a team. One person can't be PM, engineer, QA and ops at once.
  • AI help is inconsistent. Ad-hoc prompting gives ad-hoc results — no process, no memory, no guardrails.
  • Context evaporates. Every new chat starts from zero. Decisions and history get lost.
The fix

A repeatable, self-documenting AI org

Fixed roles with hard rules → predictable output. Skills encode best practice → consistency. The repo is the memory → nothing is lost. Set it up once, then just ask.

Getting Started

Four skills. That's the whole plugin.

Start a project

/asdlc-project

Zero → scaffolded repo: canonical folder layout, a 4-agent team in the project's own .claude/, seeded product & brand docs, Next.js app, first commit.

Check the setup

/asdlc-doctor

Read-only health check: prerequisites, repo context, and whether the agents and skills actually landed in this project.

Stay in sync

Automatic

Installed plugins update through the marketplace. No patch command, no zips, nothing written to ~/.claude/.

Adopt a repo

/asdlc-adopt

Bring the same 4-agent team into an already-established repo — agents, skills, and rules installed without touching existing files.

Clean up memory

/asdlc-memory-cleanup

Tidy a multi-account memory mess: narrates duplicates and stale facts, then edits only with per-item approval and a backup first.

Everything else is a workflow skill the four agents reach for — installed per project, never globally.

The Setup Path

From zero to a shipping team

1

Phase 1 — Prerequisites (Claude Chat)

Create accounts & keys: GitHub, Claude Pro, Vercel, Supabase, Gemini, Resend. Install Homebrew + git. Save a local credentials file — never committed.

2

Phase 2 — Automated setup (Claude Code)

Claude installs the CLIs, writes permissions & rules, connects Supabase MCP (one browser click), scaffolds the project, and deploys via git push.

3

Install the team

Nothing installs globally. /asdlc-project scaffolds the repo and drops the 4-agent team, workflow skills, and engineering rules into the project's own .claude/.

4

Brief the PM & go

The Product Manager gathers business context, then you simply ask — the team plans, builds, tests, publishes, and nurtures.
